# User guide

1. Open **Courses**, enter a name and choose a color. Save. Edit the name/color later; archive hides a course from new assignment choices while preserving existing assignments. Restore re-enables it. Delete is permitted only after its assignments have been moved or removed.
2. Open **Assignments**. Enter title, course, deadline, importance 1–5 and 15–1440 estimated minutes. Past dates are permitted so overdue work can be recorded. Choose To do, In progress or Done.
3. Use Edit to change any task field. Complete and Reopen change status. Delete asks for confirmation. Filtering by active/done/overdue, course, title and latest due date combines all selected conditions. The queue shows 12 rows per page.
4. **Dashboard** summarizes all tasks, including archived courses. Open “Why?” to see the priority breakdown. Adjust weights to reflect your preferences; they reset on a new connection/session. At least one weight must remain above zero.
5. **Calendar** shows deadlines by month. Add study windows with date/start/duration; overlapping or past-date windows are rejected. The proposal uses priority order, may split work across windows, does not exceed capacity and does not allocate after deadlines. Windows save automatically in SQLite. Click **Save current proposal** to persist its sessions. Replacing an existing plan requires checking the replacement confirmation; this replaces all sessions, including past sessions. Removing a window also removes its sessions. Editing tasks does not move saved sessions automatically, while deleting a task removes its linked sessions. Past windows remain visible but are excluded from new proposals. Full task estimates are treated as remaining effort, even for In progress tasks.
6. **Analytics** shows current completion and unfinished effort. The workload chart groups work by deadline, not by planned sessions. “View chart data” exposes the values as text. Export JSON downloads courses, tasks, windows and saved sessions. Under **Import JSON backup**, choose the file, inspect the validated record counts, then click **Import validated backup**. Identical records are skipped; conflicting IDs or overlapping windows reject the entire file. No existing record is overwritten. The file must be at most 2 MiB, and the combined stored/imported data must not exceed 10,000 records. Invalid files keep existing data intact. See [backup format](BACKUP_FORMAT.md).

## Recovery and accessibility

Validation errors keep your typed values. If another tab changes a record, refresh and reopen its edit form before retrying. Storage errors can mean a write succeeded but reload failed: refresh before attempting to recreate data. A red connection error offers reload. The app is local and single-user; different browsers share records but not live state.

Use Tab/Shift+Tab to traverse controls, Enter to activate buttons or submit forms, and the Skip to content link to move past navigation. Inputs have explicit labels; status updates use live regions; destructive actions require confirmation. Screens shrink to a stacked layout on mobile. Browser zoom and complete screen-reader testing still need a manual release pass.
